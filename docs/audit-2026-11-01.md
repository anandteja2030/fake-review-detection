# Model & application audit — 2026-11-01

Scope: the trained artifacts in `ml/models/`, the inference pipeline in
`ml/predictor.py` + `ml/features.py`, the Express adapter, and the
Prediction History filters. No artifact was modified and nothing was retrained.

## 1. Class mapping and probability contract — no inversion found

| Stage | Evidence |
| --- | --- |
| Saved classifiers | `lr_model`, `xgb_calibrated`, `lgb_model`, `meta_model` all expose `classes_ = [0, 1]` |
| Class lookup | `_class_1_probability()` locates the column with `classes_ == 1` instead of assuming column order |
| Meta input | one row of the three class‑1 probabilities, in LR → XGB → LGB order |
| API | `probabilities.fake = p_fake`, `probabilities.genuine = 1 - p_fake` |
| Verdict | `p_fake >= 0.47375 → fake`, otherwise `genuine` |
| Derived values | `trustScore = round((1 - p_fake) * 100)`, `riskLevel = fake→high / genuine→low` |

The verdict is always consistent with the probabilities shown, and the meta
model's arithmetic reproduces the served value exactly. **No evidence of a
fake/genuine swap in the saved pipeline.**

## 2. Why the promotional example scored 98.7 % Genuine

The example's measured inputs: 30 tokens, `promo_score = 6`, repetition 0.067,
VADER +0.98, rating gap 0.06, reference similarity 0.61. Base learners:

| Model | P(fake) |
| --- | --- |
| Logistic Regression | 0.0096 |
| XGBoost (calibrated) | 0.0328 |
| LightGBM | 0.0399 |
| Stacking meta | 0.0128 |

Three measured reasons, not a mapping bug:

1. **Promotional vocabulary carries almost no learned weight.** The LR weight
   for the scaled `promo_score` feature is `+0.0113` per standard deviation.
   Six matches ≈ +0.084 logit — negligible. The embedding block dominates
   (`mean |w| ≈ 0.72` vs `0.094` for the word TF‑IDF block).
2. **Length dominates the opposite direction.** `char_length` has weight
   `−2.196` per SD for the fake logit: longer, richer text pushes toward
   Genuine. The example is long and lexically diverse.
3. **Promotional wording is not, by itself, a fake signal.** On the
   gold‑standard Ott corpus: `P(deceptive | promo_score ≥ 4) = 0.469` versus
   `P(deceptive | promo_score = 0) = 0.524`. Promotional language is equally
   common in truthful reviews. The UI must keep saying this.

**Conclusion:** the verdict is what this model computes; it is not proof the
review is genuine, and the promotional phrasing is not evidence of deception.

## 3. Anti-correlation: short reviews are near-deterministically "Fake"

`short_flag` was almost constant in training: scaler mean `0.000`,
scale `0.019` (roughly one short review in the training data). At inference a
short review produces a scaled value of ≈ 52.6, contributing `+8.8` logit:

| Probe | Tokens | P(fake) |
| --- | --- | --- |
| “Great earbuds” | 2 | 0.800 |
| “Broke fast” | 2 | 0.813 |
| “amazing” | 1 | 0.662 |
| Repetitive 10-token text | 10 | 0.976 |

This is a real reliability defect caused by a near-degenerate scaler feature,
not by the text's meaning.

## 4. Independent evaluation on unseen labelled reviews

Corpus: Ott et al. Deceptive Opinion Spam (Chicago hotel reviews), 1,600
reviews, 800 deceptive / 800 truthful. Label semantics verified against the
upstream `data_prep.py` (`Label 1 = deceptive`). Downloaded from a public
mirror; not part of the repository.

| Metric | Value |
| --- | --- |
| Accuracy | **0.500** |
| Precision / Recall / F1 (Fake) | 0.000 / 0.000 / 0.000 |
| ROC‑AUC | **0.549** |
| PR‑AUC | 0.537 |
| Brier score | 0.488 |
| Confusion matrix | TN 800 · FP 0 · FN 800 · TP 0 |
| Predictions | 1,598 of 1,600 classified Genuine |

Base learners on the same corpus: LR AUC 0.515, XGB 0.575, LGB 0.575.
Feature-block permutation search (24 orders) peaked at AUC 0.540; TF‑IDF on raw
versus cleaned text made no difference (0.492 vs 0.494). Near-duplicate screen:
0 of 1,600 reviews reached 0.99 cosine similarity with the stored references.
The saved artifacts therefore contain **no usable generalisation signal on this
corpus**, and the reported 94.5 % accuracy could not be reproduced.

Caveat: the repository contains no training data, split indices or training
script, so it cannot be proven whether this corpus is in- or out-of-distribution
for the model. The reported metrics in `server/src/data/model_metrics.json`
remain author-provided and unverified; the app already labels them as such.

Diagnostic probe suite (12 constructed reviews, no ground-truth labels):
promotional and natural long reviews → Genuine; short and repetitive reviews →
Fake. Results in `ml/audit_probe_results.json`.

## 5. Recommended corrections (not applied — approval required)

1. **Do not ship a threshold tweak.** Changing 0.47375 cannot fix an AUC of
   0.55; it would only move the operating point.
2. **Freeze `frd-stack-v1` as-is** and add a second model version trained from a
   documented dataset and split.
3. **Fix near-constant features before retraining:** drop `short_flag` (it is
   redundant with `review_length`) or scale with a variance floor so a value
   unseen in training cannot contribute ±9 logit.
4. **Calibrate the meta-model on a validation split** (the meta is currently an
   uncalibrated LR over raw probabilities with a large negative intercept).
5. **Select the threshold on validation data**, never on the reported test set.
6. **Publish verified metrics** (accuracy, precision, recall, F1, ROC‑AUC,
   confusion matrix, calibration curve) computed on that same documented split.
7. **Report dataset provenance and label definition** in the app.

Recommended external sources for a defensible retrain: the Ott et al.
Deceptive Opinion Spam corpus (balanced, human-labelled, standard benchmark),
the Yelp Recruiting / YelpChi spam datasets, and Amazon reviews with the
Salminen et al. CG/OR labels. Validate labels by checking annotation guidelines,
inter-annotator agreement, duplicate text, and class balance before training.

## 6. Prediction History filters — root cause and fix

`useFetch(fn, deps = [])` runs its effect on `[...deps, reloadTick]`. The
History page called `useFetch(() => api.history({ category, verdict }))` with no
dependency array, so the effect ran once on mount. Changing either selector
updated React state but never re-ran the request, leaving the list unchanged.
The same bug existed in the Analytics category explorer.

Fix: load the records once, then filter them in the browser with a pure,
tested module (`frontend/src/lib/historyFilters.js`) so category, verdict and
search combine correctly, counts stay global, and reset works without a
refetch. The server's `/api/history` filter contract is unchanged.
